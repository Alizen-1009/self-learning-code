本课边界

它是什么

可运行的 FlashInfer-style 调度教学 kernel：grid=B×H、一个 CTA 持有一个完整 head state、chunks 在 CTA 内串行。

它不是什么

不是高性能 chunk kernel：内部仍逐 token recurrence，没有 KK/QK/Ainv/W/U、UMMA、TMEM 或 TMA。

1｜一个 CTA 如何持有完整 state

grid = B × H
block = 8 warps × 32 = 256 threads

完整 state 是 [V,K]=[128,128]。CTA 的 8 个 warps 各负责 16 个 V rows：

warp 0 → V[  0: 16], all K[0:128]
warp 1 → V[ 16: 32], all K[0:128]
...
warp 7 → V[112:128], all K[0:128]

每 warp 内仍使用第 6 课的逻辑 2×16 lane layout；每线程持有 8 V rows × 8 K values = 64 FP32 state values。8 个 warps 合起来覆盖完整 128×128 state，且不同 V rows 不需要跨 warp 通信。

2｜代码中的 persistent schedule

# one CTA owns one (batch, head)
head = block % H
batch = block // H
v_offset = warp_idx * 16
state_tile = load_state_rows_to_registers(v_offset)

for chunk in range(T // 64):
    for local_t in range(64):
        token = chunk * 64 + local_t
        q, k = load_full_qk_for_this_warp(token)
        v_tile = load_16_values(token, v_offset)
        state_tile = recurrent_gdn_step(state_tile, q, k, v_tile)
        store_16_outputs(token, v_offset)

store_final_state_rows(state_tile)

和第 6 课的差别只有 grid/ownership：

版本Grid一个 CTA
第 6 课B×H×81 warp，16 V rows
第 8 课B×H8 warps，完整 V=128

代价是每个 warp 都重复加载完整 q/k；收益是完整 state 在一个 CTA 内，调度形状接近 FlashInfer。

3｜与 FlashInfer SM103 的关系

本课
  • 8 warps / CTA
  • state 在 registers
  • token recurrent loop
  • 无 UMMA/TMEM/TMA
FlashInfer SM103
  • 12 warps / CTA
  • state 在 TMEM
  • C=64 的 7-GEMM chunk
  • TMA + UMMA + mbarrier

共享的核心不是具体指令，而是：

one sequence/head CTA
state stays on-chip
chunks advance serially inside CTA

4｜SM90 并行方式对比

FlashInfer SM90 普通 prefill 同样是一 CTA 对应一个 sequence/head，但配置为：

grid = num_sequences × num_heads
block = 4 warp groups × 128 = 512 threads
Warp Group职责
WG0 LD/STTMA Q/K/V、alpha、beta、output store
WG1 STATE0state/output WGMMA
WG2 STATE1state/output WGMMA
WG3 AUXKK/QK/triangular inverse

SM90 没有 TMEM，state 主要存在两个 state-math warp groups 的 WGMMA register fragments；SM103 使用 TMEM 降低 accumulator register pressure。两者都在 CTA 内按 chunk 串行，并重叠下一 chunk 的 load/local preparation。

低并行度例外

SM90 还可以由 use_cp=auto 选择 Context-Parallel 路径，把 sequence partitions/chunks 并行计算局部 affine transfer，再做 scan/fixup；当前 SM100/SM103 dispatch 不走该 CP heuristic。
