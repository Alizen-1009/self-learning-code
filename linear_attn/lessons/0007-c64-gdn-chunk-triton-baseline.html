1｜我们改变了什么？

Lesson 6 recurrent 
for token in range(T):
    state = recurrent_step(state, token)

串行链长度 T；没有 KKT/W/U/H/R。

Lesson 7 chunk 
parallel_prepare_all_chunks()
scan_chunk_states_serially()
parallel_compute_all_outputs()

串行链长度 NT=T/64；额外物化 chunk intermediates。

输入 contract 完全不变：

BF16 q/k/v [B,T,H,128]
FP32 alpha/beta [B,T,H]
FP32 V-first state [B,H,128,128]

这样 output/final state 可以直接与第 6 课 recurrent oracle 比较。

2｜五阶段 Triton pipeline

Gate/KKT → Solve → W/U → State Scan → Output
parallel　 parallel　 parallel　 serial chunks　 parallel

Stage 1：Gate cumsum + weighted KKT

grid = B * H * NT
G = cumsum(log(alpha))
gram = K @ K.T
left = I + strict_lower(beta * exp(G_i-G_j) * gram)

每个 program 负责一个 `(batch,head,chunk)`，chunks 完全独立。

Stage 2：unit-lower triangular inverse

grid = B * H * NT
Ainv = inverse_lower_triangular(left)

每个 64×64 系统独立做 row-wise forward substitution。输出 Ainv 为 BF16，供后续 dot 使用。

Stage 3：W/U

grid = B * H * NT
U = Ainv @ (beta * V)
W = Ainv @ (beta * exp(G) * K)

仍然不需要 incoming state，所以所有 chunks 可以并行。

Stage 4：State scan

grid = (B * H, V_tiles)

for chunk in range(NT):
    H[chunk] = state
    R = U[chunk] - W[chunk] @ state
    save R
    state = decay_to_end(state) + K_end.T @ R

grid 没有 NT；一个 program 持有 `[16,128]` state tile，并顺序扫描 chunks。

Stage 5：Output

grid = (B * H * NT, V_tiles)
inter = (Q * exp(G)) @ H.T
intra = weighted_causal_QK @ R
output = inter + intra

H/R 已准备完毕，所有 chunk outputs 再次并行。

与 FlashInfer 的连接

这个 baseline 故意把中间量全部物化，便于检查每一阶段。FlashInfer SM103 的主要优化方向恰恰是融合这些阶段，让 Ainv/residual/state 尽量停留在 SMEM/TMEM/register。

4｜唯一 chunk-serial 的阶段

Stage 4 中：

state[c+1] 依赖 state[c]

因此同一 `(batch,head,V-tile)` 必须：

chunk 0 → chunk 1 → ... → chunk NT−1

但不同 batch、head、V tile 仍然并行。与第 6 课相比，串行长度从 T 缩短为 NT；代价是前三阶段和第五阶段增加矩阵计算与 HBM intermediates。

5｜B300 SM103 correctness

Shape [B,T,H,D]StatePyTorch chunk rel-L2Triton rel-L2状态
[1,64,1,128]zero1.275e-33.801e-3PASS
[1,64,4,128]random1.165e-34.073e-3PASS
[1,128,2,128]zero1.212e-34.079e-3PASS
[2,128,4,128]random1.218e-34.219e-3PASS
为什么不是 0 error？

Chunk 在代数上与 recurrent 等价，但改变了 BF16/FP32 reduction 顺序。甚至纯 PyTorch chunk 与 recurrent 也有约 1.2e-3 相对误差；Triton 最大 4.219e-3，低于 BF16 baseline 阈值 1e-2。

最终状态最大 rel-L2 为 3.224e-3；4/4 cases PASS。

6｜B300 实践中暴露的三个问题

  1. 普通 Python 全局常量：Triton 3.6 不允许 kernel 捕获普通 C/D；必须使用实例化的 tl.constexpr 或显式 launch constexpr。
  2. 负索引：G[-1] 不是合法 Triton tensor index；使用 masked reduction 提取 chunk 最后一项。
  3. 错误阈值：最初用 1e-5 混淆了数学等价和浮点 bitwise 等价；保留原始误差后改用 BF16 的 1e-2 标准。
