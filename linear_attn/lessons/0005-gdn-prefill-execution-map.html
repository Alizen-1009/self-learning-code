完成标准

1｜先学会读调度，而不是读公式

Chunk-parallel 
grid = (num_chunks, B * H)

kernel[grid](...)

chunk id 来自 program/block id；不同 chunks 可同时驻留在不同 SM。

Chunk-serial 
grid = (B * H,)

for chunk in range(num_chunks):
    state = update(state, chunk)

一个 program/CTA 持有 state，并按顺序处理 chunks。

两个层次

“chunks 并行”不表示整个阶段没有依赖：chunk 内的 cumsum/triangular solve 仍有局部顺序。“chunks 串行”也不表示 GPU 只有一个线程：不同 sequence、head、V tile 仍可并行。

2｜FLA：parallel → serial → parallel

用一个固定例子：

SequenceT=256
ChunkC=64, NT=4
BatchB=1
HeadsH=2
时间 →
Gate   [c0][c1][c2][c3]　并行
A      [c0][c1][c2][c3]　并行
W/U    [c0][c1][c2][c3]　并行
State  c0 → c1 → c2 → c3　串行 / head
Output [c0][c1][c2][c3]　并行

Stage A：gate cumsum

grid = (NT, B * H)
gdn_gate_chunk_cumsum_kernel[grid](...)

每个 chunk 独立把自己的 64 个 gate 转成 cumulative gate。四个 chunks 可以同时计算。

Stage B：KKT + triangular solve

grid = (NT, B * HV)
chunk_gated_delta_rule_fwd_kkt_solve_kernel[grid](...)

每个 chunk 只依赖自己的 K、gate、beta，独立生成 solved matrix A。不同 chunks 并行；单个 chunk 内 solve 有局部下三角依赖。

Stage C：W/U

grid = (NT, B * HV)
recompute_w_u_fwd_kernel[grid](...)

所有 chunks 独立计算 W/U，因为这一步还不需要知道各 chunk 的 incoming state。

Stage D：state recurrence

grid = (V_tiles * N * HV,)

for chunk in range(NT):
    H[chunk] = state
    R = U[chunk] - W[chunk] @ state
    v_new[chunk] = R
    state = decay_and_update(state, K[chunk], R)

grid 没有 NT；每个 program 内部循环 NT，所以同一 sequence/head 的 chunks 串行。这是 FLA forward 的 chunk-level 依赖链。

Stage E：output

grid = (V_tiles, NT, B * HV)
chunk_fwd_o_kernel[grid](H, v_new, ...)

state stage 已准备好每个 chunk 的 H 和 R，所以 output 再次跨 chunks 并行。

3｜为什么保存 H 和 v_new？

H[chunk]

当前 chunk 开始前的 state snapshot。

H[0]=initial_state；H[1]=chunk0 final state。

v_new[chunk]

当前 chunk 真正写入 state 的 corrected residual R。

R=U-W@H；不是原始 V。

独立 output kernel 对 chunk c 需要：

inter output ← Q[c] 与 H[c]
intra output ← Q/K[c] 与 v_new[c]

state program 一旦继续到下一个 chunk，寄存器中的旧 state 会被覆盖。因此必须把每个 chunk 的 incoming state 和 residual 写入 global memory，供所有 output chunks 并行读取。

数据流

state scan → global H/v_new → output kernel

这增加 HBM 流量，但把 output 从 state recurrence 中解耦，并为训练/backward 保留有用中间量。

4｜FlashInfer SM103：fused streaming chunks

FlashInfer 的主要 grid 是：

persistent CTAs ≈ min(B × H, available clusters)

一个 CTA 领取一个 (sequence, head)，把 initial state 加载到 TMEM，然后：

state = load_initial_state_to_tmem()

for chunk in range(num_chunks):
    load_and_prefetch_qkv_gate_beta(chunk)
    compute_kk_qk_and_inverse(chunk)
    prediction = k_chunk @ state
    inter = q_chunk @ state
    residual = corrected_value(chunk, prediction)
    output_chunk = inter + intra_output(chunk, residual)
    store_output(output_chunk)
    state = decay_and_update(state, k_chunk, residual)

store_final_state(state)

它仍然是 chunk=64 的算法，但 chunk 不在 grid 中，而在 persistent CTA 的内部 loop 中。

为什么不保存完整 H？

当前 state 还在 TMEM 时，FlashInfer 已经计算完当前 chunk 的 inter output。无需后续 output kernel 再读取 H。

为什么不保存完整 v_new？

corrected residual 产生后，当前 CTA 立即将它用于 intra output 和 state update。无需写入 global tensor 再读回来。

它在哪里并行？

  • 不同 sequence/head 的 persistent CTAs 并行；
  • chunk 内的 7 组 GEMM 使用 Tensor Core/UMMA；
  • 12 个 warps 分工完成 TMA load、KK/QK/inverse、state/output、store；
  • 多 stage pipeline 重叠当前 chunk 计算和后续 chunk 预取。
