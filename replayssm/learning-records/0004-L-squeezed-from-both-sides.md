# 0004 · 第 4 课：`L` 被两侧夹住，以及「错得越轻越危险」

## 一 · 本课最有教学价值的发现：静默失败的严重性是**反向**的

故意漏掉 `h + 2T ≤ L` 判据，让 ring buffer 自然回绕覆盖仍需的输入，实测相对误差：

| L | 相对误差 | 有没有报错 |
|---|---|---|
| 4 | 281.8% | 没有 |
| 8 | 101.0% | 没有 |
| 16 | 36.9% | 没有 |
| 32 | **0.6%** | 没有 |

**`L` 越大错得越轻 ⟹ 越危险。** L=4 时一眼就看见；L=32 时只有 0.6%，输出量级正常、无 NaN、短序列上像「精度问题」，能一路活到 benchmark，最后表现为长上下文质量莫名下降。

这条和 learning-record 0002 里那个「漏掉 `α` → 31.8%」是同一个模式：**中等大小的误差最危险**。已把它做成第 4 课的开场（`#silent`），比任何「要小心」的说教都有效。

脚本里这条写成了**「必须失败」的断言** —— 如果哪天它「通过」了，说明模拟本身写错了。

## 二 · `L` 的两侧约束（第 1 课那笔账的完整版）

第 1 课只给了瞬时上界 `dn/(d+n) = 64`。完整的账有三项：

```
每步搬运 = 4dn (读检查点) + 4·h̄·(d+n) (读 buffer) + 4dn/周期 (flush 摊薄)
```

`L` 变大 ⟹ 第二项涨、第三项跌 ⟹ **存在最优值**：

- **`L* = √(2dn/(d+n))`**，d=n=128 时 ≈ 11；数值扫描得 **12**，收益 **1.71×**。
- 极小很**平坦**：L=8–16 都约 1.70×。
- 归零处是 `2dn/(d+n) = 128`（周期平均 vs 瞬时，故是第 1 课那个 64 的两倍。已验证 L=128 ⟹ 1.00×，与第 1 课把 h 拉到 64 时看到的临界点一致）。

**下界完全来自投机窗口**：`L ≤ 2T` ⟹ `h` 恒为 0，buffer 一次都用不上；`L ≥ 3T` 才能连做两轮、buffer 才真正非空。

**两侧一撞（d=n=128）：**

| T | 下界 3T | 取该 L 的收益 |
|---|---|---|
| 1 | 3 | 1.71×（可取 L≈12） |
| 4 | 12 | 1.71×（刚好撞上最优） |
| 8 | 24 | 1.65× |
| 16 | 48 | 1.45× |

**结论：投机窗口收两次费。** 第一次是第 3 课的 `T²` 内积（每 token `1 + T/(2h)`）；第二次是这里的「抬高 `L` 下界、逼你离开带宽最优点」。**两笔账互相独立，都要算。**这是四课账本的第一次真正交汇，也是 MISSION 里「`L` 的取值上界由什么决定」的完整答案。

另外 `L*` 随 `d`、`n` 变（d=n=256 ⟹ `L* = 16`）—— 所以 `L` 不能硬编码，必须跟 `d`/`n`/`T` 一起调。这解释了 SGLang 为什么把它做成 `--gdn-replayssm-cache-len`。

## 三 · 两个自己踩的坑（都在写组件时）

1. **把投机的收益混进了 `L` 的账。** 第一版 `flush-calc.js` 把检查点读取摊给 T 个 token，于是 T=8 时算出「8×–20× 收益」—— 那是投机解码把一次 forward 摊给 T 个 token 的效果（第 3 课的事），把 `L` 的取舍完全埋掉了。**已改：搬运账固定按非投机稳态算，`T` 只驱动下界、绝不进搬运账。**JS 注释里写明了这条分工，防止以后又合并。
2. **下界算错。** 先写成 `L ≥ 2T+1`，但 `2T < L < 3T` 时周期只有一轮、`h̄` 恒为 0 —— buffer 仍然没用。正确是 `2T` 为硬底、`3T` 才真正可用。

第 1 点值得记住：**当一个比值同时受两个机制影响时，先把它们分开各算一遍，再谈合并。**否则大的那个会把小的那个吃掉，看起来还很漂亮。

## 四 · 一处标注为「重建」的解释

`h + 2T > L` 这个判据取自博客，但**「为什么是 2T 而不是 T」博客没有展开**。我给的解释：装下本轮只需 `h+T≤L`，多留一轮是因为 `write_pos` 每 forward 只能推进一次，**不能在轮中间插 flush**，故须提前一轮保证最坏情况（`m=T`）也安全。

自洽，且把 `2T` 和 CUDA graph 约束绑在了一起（教学上很顺）。但**已在讲义与公式卡里明确标注为推断**。回查清单已记入 NOTES。

## 五 · 测试写法上的一个修正

第 5 节的断言一开始 FAIL，偏差 `9.1e-12` > `TOL=1e-13`。**不是讲义错，是测试错**：nstep=60 累积后 `y` 的量级到 `1e4`，绝对容差没有意义。已改为相对偏差（`1.6e-15` PASS），并给 `report()` 加了 `tol` 参数（此前我用「传一个负数进去」的方式绕过容差，很脏）。

教训：**断言恒等式用相对偏差，除非能保证量级 O(1)。**
