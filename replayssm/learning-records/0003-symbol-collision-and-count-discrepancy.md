# 0003 · 第 3 课：一次符号撞名，一处计数分歧

## 一 · `L` 撞名（已修，值得记住的流程教训）

写第 3 课时我给 T×T 严格下三角耦合矩阵起名 `L`（lower triangular），理由是避开博客的 `A_{s,s'}` 与衰减参数 `A` 撞名。**但 `L` 在本工作区早已被占用 —— 它是 buffer 容量**（`h + 2T > L`、`--gdn-replayssm-cache-len`）。更糟的是第 3 课正文里两种含义同时出现（「flush 把范围夹在 ≤ L 个 token 内」与「(I+L)U = R」）。

最终命名：**`C`（coupling）**。三方对照写进公式卡与 glossary：

| 含义 | 博客 | 本课程 |
|---|---|---|
| T×T 严格下三角耦合 | `A_{s,s'}` | **`C[s,s′]`** |
| 衰减参数 | `A` | `a`（每步标量门） |
| buffer 容量 | `L` | `L`（不动） |

**流程教训**：符号预算（learning-record 0001）只管了「数量」，没管「唯一性」。以后引入新符号必须先 `grep` 整个工作区确认未被占用。这次是在跑完整验证时才发现 —— 靠的是把公式卡的「符号」小节整体读了一遍，看到两个 `L` 卡片并列。**符号表并列展示能暴露撞名，散在正文里则看不出来。**

## 二 · 投机内积计数：`T(T+h)` vs `2Th + T²`

公式卡（转自博客）记的额外内积是 `T(T+h)`。我按第 3 课的推导逐项数，得到 **`2Th + T²`**，约两倍。

逐项（已写成脚本断言）：

| 来源 | 个数 |
|---|---|
| `R` 的窗口部分 | `T·h` |
| `C` 的 draft 间部分 | `T(T−1)/2` |
| `y` 的窗口部分 | `T·h` |
| `y` 的 draft 间部分 | `T(T+1)/2` |
| **合计** | **`2Th + T²`** |

**差异原因已定位**：`T(T+h)` 对应**单条读出路径**。GDN 走 state-and-output route（learning-record 0002），**需要两条**（一条出 `u`，一条出 `y`），故约为其两倍。Mamba-2 只需一条，就接近 `T(T+h)` 本身。两者同为 `Θ(T(T+h))`，**二次项的结论不变**，所以不影响教学结论，但精确数字必须标注清楚。

派生出一个更好记的量：**每 token 开销 = `1 + T/(2h)`**。`T=8,h=32` → 1.13×（二次项占 11%）；`T=16,h=32` → 1.25×（占 20%）。这条比 `T(T+h)` 有用得多，因为它直接说明「投机窗口必须远短于缓存窗口」。

⚠️ **待联网核实**：博客的复杂度到底算一条还是两条路径。这决定 `T(T+h)` 是原意还是笔误。已记入 NOTES 的回查清单。

## 三 · 一处刻意破规

第 3 课符号 15 个，超过 learning-record 0001 定的「>12 就拆课」。**有意破的**：`(I+C)U = R` 两侧都必须有名字，拆成两课会让推导和收益互相看不懂。已在讲义 header 与正文里明确坦白，并提示这一课更重。

判例：**符号预算是可以破的，但必须在讲义里写明破了、为什么破、代价是什么。**默默超标不行。

## 四 · 教学判断：诚实处理「没赢在哪」

第 3 课最容易自欺的地方：前代法在 T 上**仍然串行**，三角求解并没有消灭依赖。我把这点单独设了一节（`#why`），准确表述是「把依赖从 T 次昂贵的状态读出**压缩成**一个 T×T 小矩阵」，然后才引出显式求逆（UT transform）把残余串行也变成 GEMM。

这个区分有 kernel 层后果：`R`/`C` 是上 tensor core 的大活，求逆是留在寄存器/SMEM 的小活。**搞错了会去优化错的地方**，所以值得单独讲。
