# 0001 · 第 1 课重写：给讲义定符号预算

## 触发

用户读完第一版 `0001-decode-ledger-history-route.html` 后的判断：**「符号太多、排版不好、规划不合理」**。三条都成立，且是同一个病的三种表现。

（该文件已于 2026-08-11 经用户确认删除，取代者为 `0001-decode-byte-ledger.html`。原内容如需比对，见 commit `d57ea6a`。）

## 诊断

第一版在一课里引入了约 19 个带上下标的符号（`S_t, a_t, Δ_t, v_t, k_t, q_t, y_t, ā_t, pre_j, s_{j,t}, A, S_0, h, T, L, d, n, β_t, g_t, u_t`），其中 4 个（`pre_j, ā_t, s_{j,t}, A`）只出现一次、在本课不承担任何推理，纯粹是working memory 税。

排版问题是符号问题的下游：正文里大量 `S<sub>t</sub>` 这类内联下标，加上 `.shape-grid` 被同时挪用于三种语义（shape 参考 / 字节账 / 符号定义），视觉上无法区分层级；账本表是把 `.matrix-table`（本为衰减矩阵设计）用内联样式硬改的。

规划问题：一课干了 5 件事 —— 承接 prefill、诊断三个痛点、对比两条路线、推 output-only、算三个数字并推 `L` 上界 —— 还顺带预告了 GDN 的新公式。这是三课的量。

## 决定

1. **符号预算写进讲义头部的 pill**（本课 10 个），并在正文明确立规矩：*凡是能写成数字的一律写成数字；下标只出现在公式框里，正文不出现。* 具体做法包括把输入增益 `Δ` 折进 `v`（少一个符号，不改结论），把 `ā_t / s_{j,t}` 统一降级为「标量权重 `w`，具体形式第 3 课」。
2. **符号密度外移到 reference**。`reference/replayssm-equations.html` 与 `glossary.html` 本来就是符号该待的地方，讲义只留支点。
3. **一课一个支点**。新第 1 课的唯一支点是 `(v kᵀ) q = v (kᵀ q)` 与随之而来的字节账。`L` 上界的正式推导移交第 4 课；`w` 的形式移交第 3 课；GDN 只留一段散文，不出公式。
4. **把「读数字」换成「算数字」**。新增 `assets/ledger-calc.js`：三个滑块（d、n、h）驱动一张实时账本表 + 变色判词。用户把 h 拉到 64 时收益正好归零 —— 于是 `dn/(d+n)` 这个上界变成**可发现的**，不用推导也先有了直觉。
5. **新建 `assets/ledger.css`** 承载账本视觉语言（字节预算条、路线对比卡、真正的账本表、三答案卡、Tufte 旁注），不再靠内联样式改造 `.matrix-table`。`course.css` 与 `../linear_attn/assets/` 逐字节相同，**保持不动**，两个工作区的共享基座继续同步。

## 顺带修正的一个诚实性问题

第一版头条只说 `8dn → 4dn`（2×），但没把「每步还要读 h 个 token 的 k、v」计入。新版把这一项画进第二张预算条并明确标注：**2× 是上界，博客的头条数字只算 state traffic，读 buffer 这一项是本课程补的账。** 这既更诚实，也正好制造了第 4 课需要的那个张力。

## 对后续课程的约束

- 每课在 header 声明符号预算，超过 12 个就该拆课。
- 新符号首次出现必须当场承担推理；只用一次的符号一律移交 reference。
- 正文禁用内联下标。
- 每课至少一个「先预测、再用工具核对」的检索练习，而不是「读完讲解」。
