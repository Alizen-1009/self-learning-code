# 0002 · 更正：GDN 的代价不是带宽，是串行纠缠

## 起因

第 1 课末尾我写：GDN「只能走 state-and-output 路线，拿不到这一课的完整收益」。写第 2 课时把代数逐条数值验证，发现这句话**是错的**。

## 事实（全部经 `code/verify_replayssm_identities.py` 验证，fp64）

1. `u_t = β_t(v_t − α_t S_{t−1}k_t)` 使 GDN 更新退化成 `S ← αS + u k⊤`，与 Mamba-2 同形。偏差 `8e-15`。
2. 第 1 课的 output-only 公式**原封不动**套 `u` 即可算出 GDN 的 `y`。偏差 `3e-15`。
3. **关键**：`u` 需要的那次额外读出 `S_{t−1}k_t`，与 `S_{t−1}q_t` 形式完全相同，**同样能用 output-only 展开算出**，不需要物化 state。逐步验证偏差 `3e-15`。

所以 **GDN 和 Mamba-2 一样，从不物化、从不写回 state**。glossary 里「state-and-output route = 仍需要在某些位置物化 state」的表述也一并错了，已改。

## 真实的账

| | Mamba-2 | GDN |
|---|---|---|
| 搬运 / head / step | 96 KiB | ≈ 96 KiB（buffer 每 token 多一个标量门） |
| 写 state | 0 | 0 |
| 对检查点 mat-vec | 1 次 | 2 次 |
| 窗口内内积 | h 次 | 2h 次 |
| 算术强度 | ≈0.5 FLOP/byte | ≈1.0 FLOP/byte |

算术翻倍，但 1.0 FLOP/byte 离 GPU 算力带宽比还差一到两个数量级 —— 仍重度 memory-bound，**带宽收益基本完整保留**。

## 代价实际在哪

`u_t` 依赖 `S_{t−1}` 依赖 `u_{1..t−1}`，窗口内的 `u` 串成依赖链。普通 decode 无害（每步只新算一个，算完即**冻结**）。这个「冻结」性质正是**必须 cache `u` 而非 `v`** 的真正理由 —— cache `v` 则每步都得重放整条链，ReplaySSM 想省的全回来了。但投机解码要**同时**求 T 个 `u`，链就成了拦路虎 → 第 3 课的 `T×T` 三角求解。

## 顺带确定的两件事

- **对角衰减不影响任何结论。**NOTES 里悬了很久的「`A` 是标量还是对角」不再是 blocker：`S ← S·diag(a) + vk⊤` 可展开（衰减吸收进 `k`），偏差 `4e-16`。仍应回查原文，但不阻塞教学。
- **两个高危 bug 的误差量级已量化。**漏掉 `u` 定义里括号内的 `α` → 相对误差 **31.8%**；照搬 `v` 而非 `u` 去展开 → **105%**。前者远比后者危险，因为它不够离谱，能一路活到 benchmark。已写成脚本里的回归测试。

## 教训（对我自己）

第 1 课那句话是**从名字反推结论**："state-and-output" 听起来就该比 "output-only" 差，于是我没验证就写了「拿不到完整收益」。**术语的名字不是论证。**以后凡是比较性断言（更快/更省/拿不到），必须先落到可跑的数字。
