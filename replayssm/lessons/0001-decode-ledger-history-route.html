ReplaySSM · 第 1 课

Decode 的账本

你已经会算 prefill 的账。现在换到 decode：state 每步搬进搬出 HBM，算术强度掉到 1 FLOP/byte。ReplaySSM 用一步结合律把这笔账砍掉一半。

算法层 · 不写 kernel 约 15 分钟 前置：scalar decay LA
本课目标 你已经知道的 病灶 两条路线 支点 账本 检查 检索练习 下一课
本课唯一收获

能写出 output-only 公式，并用它算出三个数字：state traffic 8dn → 4dn、每个 buffer token 的 FLOPs 比 dn/(d+n)、以及 cache 长度 L 的上界。

你已经知道的

在 linear_attn 第 2 课 里，你把带标量衰减的 linear attention 写成了递推：状态吸收历史，输出从状态读出。Mamba-2 的形式和它是同一个东西。

St = at St−1 + Δt (vt kt⊤)   ,   yt = St qt Mamba-2 的 state 更新与读出。Tri Dao, ReplaySSM §1
St(nheads, d, n) 每个 head 一个 d×n 矩阵
vt(d,) value，列方向
kt, qt(n,) key / query，行方向
at, Δt标量 衰减与输入增益

prefill 时你把序列切 chunk，用 GEMM 把这条递推压成矩阵乘 —— 算术强度很高，是 compute-bound。decode 时序列长度是 1，chunk 没了。这就是全部麻烦的来源。

病灶：一个 d×n 的外积，换 d 个输出

把 decode 单步的工作量摊开看。设 fp32、d = n = 128，只看一个 head：

搬运8dn = 128 KiB 读 St−1（4dn）+ 写 St（4dn）
计算~O(dn) FLOPs 外积 + 缩放加 + 一次 mat-vec 读出

算术强度落在 约 1 FLOP/byte 的量级。现代 GPU 的计算/带宽比是几百比一 —— 这意味着 kernel 的时间几乎全部花在把 state 搬进搬出 HBM。博客 §2 明确指出：在混合模型里，SSM 层反而成了主要瓶颈，而不是 attention 层。

另外两个病

不可回滚。state 更新是有损摘要，原始输入被丢掉了。投机解码时 draft 被拒，你没法把 state 退回去。既有做法是每个 draft token 存一份完整 state 快照 —— 搬运量直接乘上投机窗口。

串行。验证 T 个 draft 需要每个位置的中间 state，只能一个一个算。Transformer 那种"一次 batched GEMM 验证全部 draft"的并行度拿不到。

两条路线

递推有两种等价的读法。你在 prefill 里其实已经用过第二种，只是没给它起名字。

  1. Summary route（现状）

    每步立即把新输入吸收进摘要 St−1，然后丢掉输入。摘要是唯一的真相来源。代价：每步都要读写整个 d×n。

  2. History route（ReplaySSM）

    把递推展开，写成一个衰减过的检查点，加上最近若干原始输入的加权和：

    St = Σi≤t ( Πi<j≤t aj ) Δi (vi ki⊤) history route：state 不再被保存，而是从最近输入窗口现场重建。博客 §3

    两条路线数学上完全相等。区别只在于你把什么留在内存里：摘要，还是输入。

光是换成 history route 还不够 —— 如果你老老实实按上式把 St 加出来，你仍然物化了一个 d×n 矩阵，什么都没省。真正的节省在下一步。

支点：一步结合律

整个方法压在这一行上：

(vj kj⊤) qt  =  vj (kj⊤ qt) 左边：先造 d×n 外积，再 mat-vec。右边：先做长度 n 的内积得一个标量，再缩放长度 d 的向量。

左边 dn 次乘法，右边 d + n 次。那个 d×n 的矩阵从来不需要存在。把它代进 history route，state 就被彻底消掉了：

yt = āt (S0 qt) + Σj=1..h sj,t vj (kj⊤ qt) output-only formulation。博客 §3
S0(d, n) 检查点 state，只读不写
prej= Σi≤j Δi Δ 的前缀和
āt= eA·pret 检查点到当前的总衰减
sj,t= Δj eA(pret−prej) 第 j 个输入的相对权重

注意 sj,t 的形状：它是相对距离的函数，和你在 prefill 里画的那个带衰减的下三角权重矩阵 D 是同一个东西 —— 只不过 decode 时你只需要它的最后一行。

# summary route：每步物化并写回整个 state
S = a * S + delta * torch.outer(v, k)      # d×n 读 + d×n 写
y = S @ q                                   # d×n 读（刚写完，可能还在 cache）

# history route + output-only：state 只读检查点，输入进 ring buffer
buf_k.append(k); buf_v.append(v); buf_d.append(delta)
kq = buf_k_mat @ q                          # (h,) 每个 h(n) 次乘法
y  = a_bar * (S0 @ q) + (s_col * kq) @ buf_v_mat   # 外积从未出现

伪代码用于对齐公式与数据流，不是官方实现。官方参考实现见 Johnny-Liou/ReplaySSM。

那 state 什么时候还是要写？

buffer 快满时做一次 flush：把 buffer 里的输入汇总进 S0，清空 buffer，把新 S0 写回 HBM。投机解码下的判据是 h + 2T > L（h 已缓存 token 数，T 投机窗口，L buffer 容量 —— 预留两轮窗口的余量）。博客 §5

账本：三个数字

项 summary route ReplaySSM 比
state traffic / head / step 8dn（读+写） 4dn（只读 S0） 2×
每个 buffer token 的 state 构造 FLOPs dn = 16384 d+n = 256 64×
投机验证（T 个 draft）额外内积 串行，无法 GEMM T(T+h) 二次项 代价

前两行的比值取 d = n = 128。三个数字均出自 博客 §4–§5 的复杂度分析。

一次换来三个答案

带宽：不写 state，流量减半。回滚：原始输入还在，拒绝 draft 只需把 ring buffer 写指针退回去，零快照。并行：yt 只依赖 S0 和 buffer，各 draft 位置之间没有串行依赖，验证变成 masked GEMM。

实测（Nemotron-3 / Qwen3.5，至 550B，H100 与 B300）：kernel 1.43–1.84×，端到端 1.20–1.48×；投机吞吐 1.87–1.96×；固定 HBM 预算下并发 3.0–3.3×。

检查

1. state traffic 从 8dn 降到 4dn，省掉的是哪一半？
2. d = n = 128 时 state 构造 FLOPs 约降 64×，这个比值来自？
3. 为什么 output-only route 能把投机验证变成 batched GEMM？
4. 回滚一个被拒的 draft token，需要做什么？

检索练习（合上公式再做）

问题：ring buffer 不能无限长。每步你要读 S0（4dn 字节），也要读 buffer 里 h 个 token 的 k 和 v。请推出 h 的上界，并算出 d = n = 128 时的数值。

提示：先写出 buffer 每步的读取字节数，再要求它不超过读 S0 的字节数。

buffer 每 token 存 k（n 个数）和 v（d 个数），h 个 token 共 4h(d+n) 字节。要求它不超过 4dn：

h (d+n) < d n   ⟹   h < dn / (d+n) = 64

同一个 dn/(d+n) 又出现了一次。它既是 FLOPs 的节省倍数，也是 buffer 长度的天花板 —— 因为两者问的是同一个问题："一个 d×n 矩阵，值多少个长度 d+n 的向量对？"

flush 的写回摊薄成每步 4dn/L 字节，L 取几十时可以忽略。所以 L 太小会 flush 太频繁，太大会让 buffer 读取自己变成瓶颈；最优点在同一个数量级附近。

来源说明：这条上界是本课的推导，博客给出的是 8dn → 4dn 与 64× 两个事实，未直接写出 L 的上界。SGLang 把它暴露为可调参数 --gdn-replayssm-cache-len（RFC #28511），说明实际最优值需要实测。

下一课：GDN 为什么必须 cache u

Mamba-2 的更新是"标量衰减 + rank-1 加"，所以直接 cache (v, k) 就够了。GDN 不是：

St = egt St−1 (I − βt kt kt⊤) + βt (vt kt⊤) delta rule 在 state 右边乘了一个投影矩阵。cache (v, k) 无法展开成"检查点 + 加权和"。

ReplaySSM 的修补是 cache u 而不是 v，让更新退化回 St = αt St−1 + ut kt⊤。这个 u 你其实已经见过 —— 它就是你在 WY 表示里推过的那个修正项。下一课把这条线接上，并解释为什么 GDN 只能走 state-and-output route 而不是 output-only。
