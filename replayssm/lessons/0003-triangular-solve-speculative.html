先补上第 1 课的欠账：w 到底是什么

第 1 课我把衰减权重含糊地叫做「标量权重 w」，说具体形式后面再讲。现在讲，因为这一课要用它。

它的定义就是一段连乘 —— 从某个位置到另一个位置之间，所有衰减门的乘积。既然如此，不如直接把「从哪到哪」写进记号里：

w(i → j)  ≡  ai+1 · ai+2 ⋯ aj 从位置 i 到位置 j 的累积衰减。约定 w(j → j) = 1（空乘积）。

第 1 课那个公式于是变得可读多了 —— 它其实一直在说「每个输入按它到现在的距离打折」：

y = w(0 → h) · (S0 q)  +  Σj=1..h w(j → h) · uj · (kj⊤ q) 与第 1 课的公式完全相同，只是把 w0、wj 换成了带箭头的写法。（这里已用第 2 课的 u，所以对 GDN 也成立。）
实现不做连乘

连乘几十个 0.9 会下溢。实际做法是在 log 空间用一次前缀和：记 prej = Σi≤j log ai，则 log w(i → j) = prej − prei。一次前缀和出全部权重，任意区间的衰减都是两个前缀值相减。

换回博客的写法就是 sj,t = Δj eA(pret−prej)：那个 e 的指数就是 log w(j → t)，前面的 Δj 是被我折进 v 的输入增益。见公式卡。

代价：前缀和有 cancellation 与下溢风险。第 4 课会指出 flush 顺带把这个范围夹在了 ≤ L 个 token 内 —— 这是它除了省显存之外的第二个好处。

还有一个你已经见过它的地方：w(j → t) 作为 j 和 t 的函数，正是你在 prefill 里画的那个带衰减的下三角权重矩阵。decode 时你只用它的最后一行；投机解码时你要用它的一整个 T×T 角落 —— 这就是这一课的全部内容。

病灶：投机验证的串行墙

投机解码一轮的任务：给定 T 个 draft token，同时算出它们各自的输出 y（用来判断接受到第几个），以及各自的伪 value u（接受了就要 append 进 buffer）。

第 2 课那条链让这件事看起来不可能：

u1 → S → u2 → S → u3 → ⋯ → uT 每个 u 都要先知道前一个，因为它需要在已经吸收了前面所有 draft 的状态上做一次读出。

照这条链老实做，一轮验证要 T 次完整读出，每次都要走一遍「检查点 + 整个窗口」。T 个 token 的成本是单步的 T 倍 —— 投机解码就白做了，它的全部意义就在于用一次前向换多个 token。

对照：Transformer 为什么没这个问题

attention 里第 s 个 draft 的输出只依赖输入（所有 K、V），不依赖前面 draft 的任何中间产物。所以 T 个 draft 天然可以塞进一次 batched GEMM。SSM 的麻烦在于状态是逐步累积的中间产物 —— 而 delta rule 又让这个累积依赖读出。

关键一步：把依赖分离出来

链看起来不可拆，是因为我们一直把它当成「算完一个再算下一个」。换个问法：us 里到底有多少东西真的依赖前面的 u？

记 Sh 为窗口末端的状态（h 个已提交 token 都吸收完之后）。第 s 个 draft 要读出的那个状态，是 Sh 再吸收 s−1 个 draft 之后的样子 —— 而这个东西可以用第 1 课的展开写出来：

S(s 之前) = w(0 → s−1) · Sh  +  Σs′<s w(s′ → s−1) · us′ ks′⊤ 这里的 w 走的是 draft 窗口内的衰减门。注意右边只有 Sh 和 us′ 两种东西。

代进 us 的定义（第 2 课那条），并对每一项用第 1 课的结合律把外积消掉：

u_s = β_s ( v_s − a_s · S_(s之前) · k_s )

    = β_s·v_s − β_s·a_s·w(0→s−1)·(S_h k_s)                    # 与 u 无关
              − β_s·a_s·Σ_{s′<s} w(s′→s−1)·(k_s′ᵀ k_s)·u_s′   # 依赖前面的 u

# 把 a_s 吸收进 w：a_s · w(i→s−1) = w(i→s)
    = β_s ( v_s − w(0→s)·(S_h k_s) )  −  β_s·Σ_{s′<s} w(s′→s)·(k_s′ᵀ k_s)·u_s′
      └────────────  R_s  ────────────┘     └──────── C[s,s′] ────────┘

依赖被干净地切成两半。给两半各起一个名字：

Rs(d,) = βs( vs − w(0→s)·(Shks) )。只依赖 draft 自己和窗口末端 —— 全部 T 个可以一次并行算完。
C[s,s′]标量 = βs·w(s′→s)·(ks′⊤ks)。只在 s′ < s 时非零 —— 严格下三角。
us = Rs − Σs′<s C[s,s′] · us′ 这就是公式卡与博客里那条式子（原文把 C 记作 As,s′；我改用 C，一是避免和衰减参数 A 撞名，二是直接把「严格下三角」写进名字）。
耦合强度就是 key 的重合度

盯住 C[s,s′] 里的 ks′⊤ks：两个 draft 之间的耦合，正比于它们 key 的内积。如果所有 draft 的 key 两两正交，C 全是 0，T 个 u 彼此完全独立 —— 链根本不存在。

这很符合直觉：delta rule 的干扰来自「往同一个 key 方向反复写」。写到互不相干的地方，就互不干扰。这条已数值验证（C 最大元 6e-17）。

写成矩阵：一个 T×T 的三角系统

把 T 个 us 堆成一个 T×d 的矩阵 U（每行一个 draft），R 同理。上面那条式子就是：

(I + C) · U = R   ⟹   U = (I + C)−1 R C 是 T×T 严格下三角，所以 I + C 单位下三角 —— 行列式恒为 1，永远可逆，不需要任何数值上的担心。

为什么这算胜利 —— 以及它没赢在哪

这里必须小心，容易自欺。三角求解用前代法做，在 T 上仍然是串行的：先出 u1，才能出 u2。链并没有消失。

赢的地方在于链上串的东西变了：

  • 之前T 次完整读出串行。每次都要走一遍检查点加整个窗口，每次都是 O(d(n+h)) 的搬运与计算。
  • 之后T 次标量代入串行。R 和 C 已经算好了，前代只是在 T×d 的小块上做加减 —— 不碰检查点，不碰窗口，没有新的显存流量。
  • 而且贵的那两样（R 和 C）本身完全并行：R 是一次批量读出（GEMM），C 是一次 T×T 的 key-key 内积（GEMM）。

还能更进一步。I + C 只有 T×T，小到可以显式求逆（这正是 UT transform 的做法），于是连前代都省了：

U = (I + C)−1 · R 一次 T×T 乘 T×d 的 GEMM，在 T 上完全并行。已验证与三角求解逐位等价（偏差 4e-16）。
所以准确的说法是

三角求解没有消灭串行依赖，它把依赖从「T 次昂贵的状态读出」压缩成「一个 T×T 的小矩阵」。而这个小矩阵可以整个求逆，于是最后连那点串行也变成了一次 GEMM。

这个区分不是吹毛求疵。它决定了 kernel 该怎么写：R 和 C 是要上 tensor core 的大活，求逆是留在寄存器/SMEM 里的小活。搞错了就会去优化错的地方。

y 也是一次 masked GEMM

U 解出来之后，输出就没有任何依赖问题了 —— 直接套第 1 课的公式，只是求和范围到 s 为止：

ys = w(0 → s) · (Sh qs)  +  Σs′≤s w(s′ → s) · us′ · (ks′⊤ qs) 那个 s′ ≤ s 就是 causal mask。所有 T 个 y 一次算完。已验证 ≡ 串行结果（偏差 9e-15）。

注意 Sh 全程没有被物化：Shks 和 Shqs 都用第 1 课的展开（检查点 + 窗口）算出来。整条投机验证路径上，那个 d×n 矩阵依然一次都没出现。（验证偏差 1e-14。）

回滚就更简单了：接受到第 m 个，就把 buffer 的写指针停在 h + m。被拒的那几个 u 是算出来了没用上 —— 算错的东西从来没进过状态，所以没有任何东西需要撤销。

账本：二次项从哪来

投机验证的开销全部是内积，分四份：

每 token 开销 = (2h + T) / 2h = 1 + T / (2h) 投机窗口相对缓存窗口越短，越接近免费。T=8, h=32 时只多 12.5%。

检索练习（合上讲义）

第一题 · 最小非平凡情形。取 T = 2，把 u1 和 u2 完整写出来（不要留 Σ）。然后回答：u1 为什么不需要"求解"？

第二题 · 一个极限。如果所有 draft 的 key 两两正交，C 会变成什么？这在算法上意味着什么？反过来，如果 T 个 draft 的 key 完全相同呢？

第三题 · 账本。T = 16、h = 32 时，一轮验证的内积总数是多少？二次项占几成？每 token 开销是几倍？（先算，再用上面的算盘核对。）

1. C 的第一行是空的，所以：

u1 = R1
u2 = R2 − C[2,1] · u1 = R2 − C[2,1] · R1

u1 不需要求解，是因为它前面没有任何 draft 可以干扰它 —— 它读出的状态就是 Sh 本身，而 Sh 是已知量。严格下三角的第一行必然为空，这是通用的自检点。

2. key 两两正交 ⟹ ks′⊤ks = 0 ⟹ C = 0 ⟹ U = R：T 个伪 value 完全独立，链根本不存在，一次 GEMM 就全出来了。语义上很自然 —— delta rule 的干扰来自「往同一个 key 方向反复写」，写到互不相干的地方就互不干扰。

反过来 key 完全相同（ks = k 对所有 s）：C 的每个下三角元素都含同一个 ‖k‖²，耦合最强 —— T 个 draft 在抢同一个槽位反复覆盖。这时三角求解省不掉任何东西（依赖是真实的），但它仍然把这份真实依赖压缩到了 T×T 的小矩阵里，而不是 T 次全状态读出。三角求解不是在绕过依赖，是在给依赖找一个便宜的容器。

3. 2Th + T² = 2·16·32 + 256 = 1024 + 256 = 1280。二次项占 256/1280 = 20%。每 token 内积 1280/16 = 80，单步 decode 是 2h = 64，开销 80/64 = 1.25× —— 也就是 1 + T/(2h) = 1 + 16/64。
